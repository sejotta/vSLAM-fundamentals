01 · Dos entregables

Un mismo motor, dos formas de demostrarlo

Los dos entregables comparten la misma base de visión: detección y emparejamiento de puntos, geometría epipolar, triangulación y PnP. La diferencia está en el alcance: reconstrucción desde varias vistas o reconstrucción incremental a lo largo de una secuencia.

Fundamentos multivista

Geometría, homografía y reconstrucción 3D

A partir de dos o más vistas calibradas, el código estima la relación geométrica entre imágenes, recupera la pose relativa de la cámara y triangula una nube de puntos 3D. Es la base matemática que después usa el entregable incremental.

2 vistas→H / F RANSAC→ E = KᵀFK→R, t→ triangulación→nube 3D

Qué incluye

  • Detección y matching con SIFT + ratio test; adaptador opcional para SuperPoint + SuperGlue.
  • Homografía con RANSAC y mosaico acumulativo.
  • Matriz fundamental, líneas epipolares y epipolos.
  • Matriz esencial, recoverPose y chequeo de quiralidad.
  • Triangulación DLT con filtros de profundidad, reproyección y ángulo.
  • PnP con RANSAC para cámaras adicionales y exportación de trayectoria.
H + F + Egeometría completa
RANSACrobusto a outliers
3Dnube coloreada

Ideal para: prácticas de geometría multivista, reconstrucción de objetos, calibración, AR y demostraciones de estructura-from-motion.

Reconstrucción secuencial

vSLAM incremental con PnP

A partir de una secuencia de keyframes, el mapa se construye incrementalmente: cada nueva cámara se localiza con PnP contra los puntos 3D que ya existen, y los matches que aún no tienen punto 3D se triangulan y se añaden al mapa.

secuencia→keyframes→ matching→PnP→ nuevos puntos→mapa + BA

Qué incluye

  • Selección automática de keyframes por flujo óptico acumulado.
  • Asociación 3D–2D entre puntos del mapa y keypoints de la nueva vista.
  • Localización por PnP con RANSAC y fallback por pose relativa.
  • Triangulación incremental de los matches sin punto 3D.
  • Refinamiento alterno tipo bundle adjustment.
  • Evaluación con Sim(3), ATE/RPE y escena sintética de regresión.

02 · Cómo funciona

Del píxel a la nube de puntos

El pipeline está dividido en módulos pequeños y verificables. Esta es la ruta completa, desde una imagen hasta una pose y un punto 3D.

01

Keyframes

Movimiento acumulado con Lucas–Kanade. Se queda con las vistas que aportan baseline.

02

Features

SIFT (o SuperPoint) detecta puntos; ratio test o SuperGlue empareja descriptores.

03

F + E

RANSAC estima la matriz fundamental; E = KᵀFK la lleva a coordenadas normalizadas.

04

Pose relativa

recoverPose elige la solución con los puntos delante de ambas cámaras.

05

Triangulación

DLT con P = K[R|t]; se filtran puntos por profundidad, reproyección y ángulo.

06

PnP

La nueva keyframe se localiza con 3D–2D: solvePnPRansac devuelve T_cw.

07

Nuevos puntos

Los matches sin 3D se triangulan con las dos últimas poses y se añaden al mapa.

08

Refinamiento

PnP + triangulación alternos reducen el error de reproyección y la deriva.

El bucle que hace crecer el mapa

La clave del entregable 2 no es triangular una vez, sino repetir este ciclo con cada keyframe. El mapa deja de ser una foto fija: se convierte en la referencia para localizar la siguiente cámara.

01

PnP

3D del mapa + 2D de la nueva imagen → pose de la cámara.

02

Triangular

Matches sin 3D + dos poses → puntos nuevos en coordenadas mundo.

03

Asociar

Cada punto queda ligado a sus keypoints y observaciones.

04

Refinar

BA alterno: se ajustan poses y puntos para bajar el error.

Dos vistas: la inicialización

El primer par de keyframes estima F, lo convierte en E, recupera R, t y triangula el primer conjunto de puntos. La cámara 0 define el origen del mundo.

Secuencia: el crecimiento

Cada nueva keyframe reutiliza los puntos ya triangulados para PnP. Después aporta estructura nueva con los matches que aún no tenían profundidad. Así el mapa cubre cada vez más escena.

03 · Por qué funciona

La geometría detrás del código

No es una caja negra: cada paso resuelve una ecuación concreta. Estas son las piezas matemáticas que hacen que PnP y la triangulación incremental sean consistentes.

Proyección pinhole modelo

x ~ K [R | t] X_w

Un punto 3D del mundo se proyecta en píxeles con la matriz intrínseca y la pose de la cámara.

Restricción epipolar F

x₂ᵀ F x₁ = 0

Para un punto en la imagen 1, su correspondiente en la imagen 2 debe caer sobre una línea epipolar.

Matriz esencial E

E = Kᵀ F K

La misma geometría, pero en coordenadas normalizadas. De aquí salen las cuatro soluciones de pose.

Pose relativa R, t

X₂ = R X₁ + t

La solución correcta es la que deja los puntos triangulados delante de ambas cámaras (quiralidad).

Triangulación DLT

A X = 0 → SVD

Cada correspondencia aporta dos ecuaciones; el último vector singular da el punto 3D homogéneo.

PnP 3D–2D

x ~ K [R | t] X_3D

Con puntos 3D ya conocidos y sus observaciones 2D, RANSAC resuelve la pose de la nueva cámara.

Refinamiento BA

min Σ ‖π(T_cw, X) − x‖²

Se alternan PnP para las cámaras y DLT para los puntos; el error de reproyección baja.

Evaluación Sim(3)

aligned = s · R · x + t

La escala monocular es ambigua. Umeyama alinea la trayectoria antes de calcular ATE/RPE.

Por qué PnP después de triangular: PnP no necesita volver a calcular la estructura que ya está en el mapa. Usa los puntos 3D existentes para localizar la cámara, y luego la nueva pose sirve para triangular los puntos que faltaban. Es un ciclo que se retroalimenta: más mapa → mejor localización → más puntos → mejor mapa.

Supuestos que deben cumplirse

  • Cámara calibrada y imágenes corregidas de distorsión.
  • Escena con textura y movimiento con paralaje suficiente.
  • Solapamiento entre keyframes para encontrar correspondencias.
  • Escena mayoritariamente estática durante la captura.

Límites honestos

  • La escala no es métrica sin IMU, LiDAR o una referencia.
  • Sin loop closure, la deriva crece en secuencias largas.
  • Una escena casi plana o una rotación pura degradan F/E.
  • No hay relocalización tras pérdida de tracking.
04 · Cómo aplicarlo

De la demo a tu propio proyecto

El código está pensado para integrarse como una librería pequeña. Puedes usar los scripts tal cual o importar las clases desde Python.

Robótica indoor

Localización visual de un robot con cámara calibrada y mapa disperso de referencias.

AR / medición

Estimación de pose de cámara y estructura para superponer objetos o medir escenas.

Escaneo 3D

Reconstrucción de objetos o estanterías a partir de una secuencia de fotos.

Docencia

Un ejemplo legible de SIFT, F/E, triangulación, PnP y bundle adjustment.

Uso como librería

Las imágenes deben estar en RGB y sin distorsión. Los scripts de demo ya hacen ese preprocesado.

python · pipeline 
from vslam.camera import Camera
from vslam.features import SiftMatcher
from vslam.pipeline import IncrementalSlam, SlamConfig

camera = Camera(
    fx=641.84, fy=641.17,
    cx=311.14, cy=244.66,
    width=640, height=480,
)

matcher = SiftMatcher(max_features=2000, ratio=0.75)
slam = IncrementalSlam(
    camera,
    matcher,
    SlamConfig(max_depth=50.0, refine_iterations=3),
)

result = slam.run(images, keyframe_indices)
# result.poses  → (N, 4, 4) T_wc
# result.points → (M, 3) nube 3D

Uso desde consola

Los scripts incluyen la demo real, el runner genérico y el test de regresión sintético.

bash · scripts 
# Demo real incluida (5 frames del bookshelf)
python scripts/run_bookshelf_demo.py

# Tu propia secuencia calibrada
python scripts/run_sequence.py \
  --images path/to/frames \
  --fx 641.84 --fy 641.17 \
  --cx 311.14 --cy 244.66 \
  --dist -0.0233 0.2523 0 0 -0.5219

# Test sintético con ground truth
python scripts/run_synthetic_slam.py

Parámetros que conviene entender

ParámetroQué controlaValor de la demo
max_featuresNúmero máximo de keypoints SIFT por imagen.2.000
ratioUmbral del ratio test de Lowe; menos matches, más fiables.0,75
f_ransac_thresholdDistancia epipolar máxima para considerar un inlier.0,8 px
max_reproj_errorError de reproyección máximo al aceptar un punto triangulado.2,5 px
max_depthProfundidad máxima; evita puntos en el infinito.50,0
min_triangulation_angleÁngulo mínimo entre rayos; evita triangulaciones mal condicionadas.0,5°
refine_iterationsBarridos de refinamiento alterno.3
keyframe_thresholdFlujo óptico acumulado para crear una nueva keyframe.25 px en secuencias
Checklist de datos: calibración intrínseca, distorsión, imágenes ordenadas por tiempo, textura suficiente, solapamiento entre vistas y movimiento con paralaje. Sin esos ingredientes, la geometría no tiene información suficiente para resolver la escena.
